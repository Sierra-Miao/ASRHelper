# 中文长会议说话人模型

本项目默认采用 ERes2NetV2，保留 CAM++ 供比较。二者均在本机提取声纹，不向外部服务发送录音。网页“语音模型 → 说话人模型”可独立选择，设置保存于 `data/speaker_settings.json`。单模型及双模型共用所选说话人模型，任务记录保存实际使用的后端。历史 Excel 不会自动改写，需重新上传原录音。

## 选择依据

接入模型是 `iic/speech_eres2netv2_sv_zh-cn_16k-common` 的 `v1.0.2` 权重，约 17.86M 参数、权重约 72 MiB，采用约 20 万中文说话人训练。

该模型的[官方模型卡](https://modelscope.cn/models/iic/speech_eres2netv2_sv_zh-cn_16k-common)报告：同为约 20 万说话人训练，在 CN-Celeb 测试集上，CAM++ EER 为 4.32%，ERes2NetV2 为 3.81%。这是**说话人验证等错误率 EER**，不是一小时会议的**说话人分离错误率 DER**。其他训练设置的 [3D-Speaker 基准](https://github.com/modelscope/3D-Speaker#benchmark)中，CAM++ / ERes2NetV2 的 CN-Celeb EER 为 6.78% / 6.14%；这些数字不可混用，也不能视为本项目的会议错误率。

选择 ERes2NetV2 是基于中文声纹验证表现、CPU 可运行、可直接取得官方开放权重和对现有环境的兼容性。尚未在用户这一小时会议上完成带人工标注的 DER 对照，不能保证实际录音一定改善。

## 指定人数与长录音

FunASR 的声纹流水线在 VAD 范围内提取重叠短窗，再对整段录音聚类。指定人数只能约束组数，不能证明每句话的身份正确。输入的人数应为实际出声人数，不含始终沉默的参会者。

旧版平均链接层次聚类在用户会议中发生了明显退化：指定 8 人时，约 2948 秒被标为同一人，其余组几乎仅有数秒；00:10–00:50 全部标为同一人。指定簇数的树切割会将簇数消耗在少量离群点上，并把真实不同的人不可逆地合并。该反馈说明声纹验证 EER 和简单双人测试不足以验证长会议分离质量。

ERes2NetV2 现改为 L2 归一化后的 K-Means：对整段录音统一分组，固定随机种子，20 次初始化，采用 Lloyd 迭代，不再进行层次合并，也不压缩掉原始窗口。没有要求每人发言时长相等。内存不需要 N×N 距离矩阵，声纹与标签存储随窗口数增长。指定人数仍是强约束，并不能保证说话人分组正确；只说过很短几句话的人、噪声和重叠发言仍有风险。

未指定人数时，保留 FunASR 原有的自动人数估计及其短录音限制；CAM++ 模式也保留原聚类与转写流程。说话人编号按首次出现顺序规范化。ERes2NetV2 指定人数分支没有“少于 20 个短窗直接判成同一人”的限制。

ERes2NetV2 现在先检测音频换人，再对各轮次分别转写。VAD 内采用 1.5 秒窗口、0.5 秒步长提取声纹，短 VAD 区域保持实际音频长度，不补静音到 1.5 秒。相邻窗口标签变化时，以窗口中心的中点作为切点；检测到的短轮次不会再被原流水线不足 0.7 秒的平滑规则强制抹掉。每段音频只包含一个检测到的说话人，避免先识别成长句、再用多数时长覆盖另一人的短发言。转写输入最长 30 秒，较长轮次均分以避免遗留极短尾块。此流程复用已加载的 VAD、声纹、ASR 和标点模型，不修改第三方安装文件。

这些时间是音频窗口分辨率下的估计，不是精确的字级或音素级对齐。1.5 秒窗口仍可能混入两个人的声音，半秒以内的短应答可能无法检测，重叠讲话不能分离为独立音轨。后续段落整理仍只合并已识别的同一人连续行；没有按字符估算时间或将一句话拆成词。

## 环境与文件

复用现有 PyTorch、torchaudio、NumPy、SciPy、scikit-learn、ModelScope，不添加 pyannote / NeMo 环境，也不修改 `.venv` 内的第三方代码。ERes2NetV2 实现保存在 `backend/vendor/eres2net/`，来自固定官方提交，保留 Apache-2.0 授权、来源和版权说明；注册适配器为本项目代码，不执行远程模型代码。权重首次下载至 `models/`，启动检查能识别缺失模型并引导网页下载。权重、配置和测试结果均已被 Git 忽略。

相较 CAM++，新模型推理通常更慢；0.5 秒步长也比原来的 0.75 秒步长增加了约一半窗口。CPU 长会议还需承担逐窗声纹提取时间，不能仅凭聚类测试耗时估计总转写时间。系统内存建议至少 8 GB，实际可用量要同时容纳 ASR、解码音频和聚类。一小时连续语音约 7200 窗口，无需二次方距离数组。

## 验证范围

- 严格加载官方权重，557 个状态项全部匹配。
- 本机 CPU 对真实双人 A → B → A 样例提取声纹，三个片段输出 192 维向量，固定两人时恢复 A → B → A 身份关系。
- 回归检查固定人数、短录音、4800 及 12000 个合成短窗、离群点不吞并两组主要说话人、全程编号、网页切换及失败保留原设置。细粒度检查覆盖 0.5 秒换人轮次、0.3 秒孤立短应答、按音频分段转写、静音和尾部覆盖。合成声纹与模拟转写测试只验证流程、规模与一致性，不证明真实会议的准确率。

初次接入时 47 项回归测试通过，双人样例通过；这不足以覆盖已发现的 8 人长会议退化。改为先分人后转写后，真实双人样例输出 3 个轮次，保持 A → B → A 并成功导出 Excel。用户 00:10–00:50 的本机声纹诊断与全场抽样对照结果保存在忽略的 `test-results/` 中；抽样不是全场人工标注 DER 评估。

当前回归检查：55 项测试通过，覆盖离群点占组、短轮次保留、先切音频后转写以及接口和 Excel 回归。若超过 95% 的声纹窗口归为同一人，结果页会提示核对；真实主讲人占比很高也可能触发该提示。

针对用户反馈的诊断：按全场每 5 秒取一个 3 秒片段，共提取 665 个非极低能量参考声纹，再与 00:10–00:50 的 78 个密集窗口共同按 8 人分组。在同一组抽样数据上，旧 AHC 最大组为 590 / 743 窗口，新 K-Means 最大组为 215 / 743。目标片段不再全部归为一人，但仍出现 4 个标签（两个主要组 28、40 窗口，其他组 9、1 窗口），所以不能声称已准确还原用户所说的两个人。这是存在静音、参考窗口长度不同的抽样诊断，不是完整 VAD 后全场识别或人工核对的准确率评测。
